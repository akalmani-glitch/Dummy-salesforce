Top fields default to a read-only view (as if extracted); beneficiary tables are always editable

Saved records are stored server-side in a real database (via /api/accounts), not browser localStorage — they persist across devices and are readable by anyone with the account URL, by design, since this tool only ever holds dummy test data. The GET endpoints require no authentication, so an external AI assistant or script can fetch an account's JSON directly. Only this page's own Save button can write; there is no external write endpoint. The same read API is the path to wrapping this as an MCP connector later, so a Claude conversation using the beneficiary-review skill could read this client record directly.

Client Docs, Account Notepad, and Account Details & Client Info remain working shells (add/edit/remove rows, no rules attached) pending your input on the doc-type-to-form mapping and notepad-to-authorization linking. Beneficiary tab rules: Section A (Scan Title, Document Date, State Code) plus Section B (DOB, SSN/TIN, Relationship, allocation method/value, contingent count, added/removed beneficiaries, signer vs. Owners & Roles).
