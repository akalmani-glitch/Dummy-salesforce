This is a standalone file — no Claude dependency. It runs entirely in your browser using local storage, so saved accounts persist across reloads on this device/browser, but are NOT shared with other people or other machines. To make this a genuinely multi-user shared tool (what "sharable" really requires), it needs a real backend — a hosted database and API this page talks to instead of localStorage. Common low-effort options: Firebase or Supabase (free tier, you create the account); or a small custom API on your organization's own infrastructure if you have engineering support. Once a backend exists, the same backend can be wrapped as an MCP connector so a future Claude conversation using the beneficiary-review skill could read and write this client record directly — that's the path to genuine automation we discussed earlier, rather than manually relaying data between this tool and a chat.

Client Docs, Account Notepad, and Account Details & Client Info remain working shells (add/edit/remove rows, no rules attached) pending your input on the doc-type-to-form mapping and notepad-to-authorization linking. Beneficiary tab rules: Section A (Scan Title, Document Date, State Code) plus Section B (DOB, SSN/TIN, Relationship, allocation method/value, contingent count, added/removed beneficiaries, signer vs. Owners & Roles).
